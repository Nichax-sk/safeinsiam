# CLAUDE.md

Guidance for Claude Code when working in this repository.

## 1. Project overview

SafeInSiam is a monorepo laid out as follows:

- `frontend/`: Nuxt 4 web app
- `backend/`: Go API built on Gin
- `docker-compose.yml` (repo root): defines the PostgreSQL service
- `database/`: set aside for database-related files. It currently holds only the empty `migrations/` and `seeds/` folders.

The project is an early scaffold. The backend has only health-check endpoints and the frontend has one placeholder page. Product features and requirements are not defined in the repo yet, so don't assume them.

## 3. Backend (`backend/`)

Go module `github.com/Nichax-sk/safeinsiam`, `go 1.27.3`.

| Dependency | Version |
|---|---|
| github.com/gin-gonic/gin | v1.12.0 |
| github.com/jackc/pgx/v5 (pgxpool) | v5.12.0 |
| github.com/joho/godotenv | v1.5.1 |

Layout:

- `main.go`: loads config, opens the DB pool, sets up the Gin router (`gin.Logger`, `gin.Recovery`, trusted proxies disabled), and shuts down gracefully on SIGINT/SIGTERM (10s timeout).
- `internal/config/config.go`: reads environment variables. It loads `../.env` relative to the working directory, and variables already set in the environment take precedence.
- `internal/database/postgres.go`: `NewPostgresPool` with MaxConns 10, MinConns 2, MaxConnLifetime 1h, MaxConnIdleTime 30m, HealthCheckPeriod 1m. It pings the database on startup.

Routes:

- `GET /health`: liveness check
- `GET /health/db`: pings the database (3s timeout); returns 503 if it can't connect

The server listens on `127.0.0.1:${APP_PORT}` (default 8080).

Environment variables `config.go` reads (the same names as the root `.env` and Docker Compose):

| Variable | Default | Required |
|---|---|---|
| `APP_ENV` | `development` (loaded but not used yet) | no |
| `APP_PORT` | `8080` | no |
| `DB_HOST` | `127.0.0.1` | no |
| `POSTGRES_PORT` | `5432` | no |
| `POSTGRES_DB` | none | yes |
| `POSTGRES_USER` | none | yes |
| `POSTGRES_PASSWORD` | none | yes |
| `DB_SSLMODE` | `disable` | no |

## 4. Environment configuration

- **The root `.env` is the single source of truth.** Docker Compose and the Go backend both read it and use the same variable names (`POSTGRES_*`, `DB_HOST`, `DB_SSLMODE`, `APP_ENV`, `APP_PORT`).
- **The root `.env.example` is the setup template.** Copy it to `.env` only if the root `.env` does not exist yet, then replace the placeholder `POSTGRES_PASSWORD` with a secure password. Never overwrite an existing `.env`: it may hold the user's real local credentials. See Section 6 for the full local development steps.
- `backend/.env.example` lists the same keys for reference. The backend doesn't load a `backend/.env`.
- The backend loads `../.env` relative to its working directory, so it **must be started from `backend/`**. Variables already set in the process environment override values from the file.
- `.env` is gitignored. Never commit, stage, print, or overwrite it.

## 5. Database

- `docker-compose.yml` runs one service, `postgres` (`postgres:17-alpine`).
- It binds to `127.0.0.1:${POSTGRES_PORT:-5432}`, stores data in the named volume `postgres_data`, and has a `pg_isready` healthcheck.
- Credentials come from the root `.env` (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_PORT`), the same file the backend reads.
- `database/migrations/` and `database/seeds/` exist but are empty (and untracked). No migration tool has been chosen yet.

## 6. Local development

**One-time setup (from repository root, only if the root `.env` does not exist yet):** create the root `.env` from the template:

```bash
cp .env.example .env
```

Then, in the new `.env`, replace the placeholder `POSTGRES_PASSWORD` with a secure password.

> **Warning:** If a root `.env` already exists, do **not** run the copy command. Never overwrite an existing `.env`: it may hold the user's real local credentials.

Run each service in its own terminal, in this order. Open every terminal at the repository root: the `cd backend` and `cd frontend` commands below are relative to it. The backend and frontend keep running in the foreground.

**Terminal 1 — Database (from repository root):**

```bash
docker compose up -d
```

**Terminal 2 — Backend (from repository root):**

```bash
cd backend
go run .
```

The backend has to run from `backend/` because it loads `../.env` relative to its working directory.

**Terminal 3 — Frontend (from repository root):**

```bash
cd frontend
npm install
npm run dev
```

`npm install` runs `nuxt prepare` as a postinstall step.

Local URLs:

- Backend: http://127.0.0.1:8080 (health checks: `/health`, `/health/db`)
- Frontend: http://localhost:3000

## 7. Build and test

- Frontend: `npm run build`, `npm run generate`, `npm run preview`
- **Tests:** none exist yet. There are no Go `_test.go` files and no frontend test framework or script.

## 8. Coding conventions (as seen in the existing code)

- Go: application packages live under `backend/internal/`.
- Go: wrap errors with context, e.g. `fmt.Errorf("create database pool: %w", err)`.
- Go: put a `context.WithTimeout` on every DB call (health ping 3s, startup ping 5s).
- Go: read configuration only from env vars, using `getEnv(key, fallback)` for optional values and failing fast when a required value is missing.
- Frontend: style with Tailwind utility classes. No other frontend conventions exist yet.

## 9. Git workflow and safety rules

- Default branch: `main`. Commit messages use the conventional-commit style (`chore: ...`).
- Real `.env` files hold local secrets and must never be committed. `.env` is gitignored.
- `.env.example` files hold safe placeholder values and should be committed.
- Keep the example env files (root `.env.example` and `backend/.env.example`) in sync with the variables the app actually reads (`backend/internal/config/config.go`, `docker-compose.yml`). When you add, rename, or remove a variable, update both example files in the same change.
- Never print or echo values from `.env`.
- Don't run destructive commands without explicit approval. That includes `docker compose down -v`, which deletes the `postgres_data` volume, `git reset --hard`, and force pushes.
- Don't install packages, commit, push, or create branches unless the user asks.
- Ignored local clutter you shouldn't rely on: `.history/`, `frontend/*.backup`, `frontend/npm-audit.json`, `.nuxt/`, `.output/`.

3. `frontend/README.md` is still the Nuxt starter template.
